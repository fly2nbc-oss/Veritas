# AGENTS.md

Veritas (Latin “truth”) is a **lean, local tool for MD5 checksums and file integrity checks**, for Windows and Linux: open a folder, create `{folder name}.md5`, later verify what changed, and on a mismatch report whether a media file is still structurally intact. The interface is **egui/eframe on OpenGL (glow)** – no web view. This file is for AI agents (Claude Code, Codex, Cursor, Copilot …) and equally readable for people; `CLAUDE.md` only imports it.

## Standards

This project follows the latest versions of three documents from the maintainer's
standards collection (outside this repository): `repo_standard_v*.md` (setup, docs,
CI, release), `ui_design_system_v*.md` (UI) and `QUALITY.md` (checks;
`scripts/quality.sh` in this repository runs them). Read them before changing those
areas; where this file says something different, this file wins.

## Quality

Rules from `QUALITY.md`. Check script: `scripts/quality.sh`.

- At the start of a task and whenever a check fails unexpectedly: `scripts/quality.sh doctor`. It checks that tools, versions and paths fit the project. Don't rely on earlier assumptions, the real state counts. On `FEHLT` (missing) lines or deviating versions: ask, don't adapt the project's settings.
- After every code change: run `scripts/quality.sh lint` and fix what it reports.
- New function or bug fix: write a test for it in the same step.
- After every finished step: run the unit tests of the module concerned.
- Before the commit: `scripts/quality.sh all` must be green.
- Done means: the tests have run and are green. Show the output in the report.
- Never delete, disable or weaken tests to make them green.
- Never use `--no-verify`. Never switch off lint rules without asking.
- Don't build in exceptions (`#[allow]`, `#[expect]` and the like) to get around a check. If the guard check reports a finding: fix the cause. If the exception is really needed: ask a human.
- `scripts/quality.sh approve` and `.quality-approvals` only on explicit instruction from a human. `scripts/quality.sh coverage-update` likewise, when it lowers the coverage.
- No keys, tokens or passwords in the code. Vulnerability in a dependency: update the dependency. `osv-scanner.toml` only on explicit instruction from a human.
- Never commit or push directly to `main`. Work on a branch, merge only through a pull request with green CI. (Until `main` has branch protection, releases follow the steps under *Release*.)
- If a check fails and the cause is unclear: stop and ask.
- `unsafe` exists only in three Windows functions (`drive::seek_penalty`, `system::no_trash`, `tree::filesystem_roots`), each with `#[allow(unsafe_code)]` and a `// SAFETY:` comment on every block; otherwise `unsafe_code = "deny"` applies (`[lints]` in `Cargo.toml`). The exception is granted per function instead of per module (narrower than QUALITY.md §9). Rust requires `unsafe` for every C call; Veritas builds the parameters itself (NUL-terminated UTF-16, lengths from `len()`/`size_of`, handle closed exactly once), paths from a `.md5` never reach these functions. A crate such as `sysinfo` would only move the `unsafe` into third-party code and grow the exe and the supply chain.

## Rules

- Comments and docs are English. The UI speaks five languages; its texts live only in `src/i18n/`.
- The program does not crash: a strict profile under `[lints]` in `Cargo.toml` (among others `unwrap_used`, `expect_used`, `panic`, `string_slice`) and `#![deny(…)]` in `main.rs` and `lib.rs`; tests may (`clippy.toml`).
- Before every commit: `scripts/quality.sh all` (see *Quality*). Commits with `Co-Authored-By: Claude …`.
- Push and tags only when the maintainer says so.
- Test the interface headless; do not drive the real desktop with simulated keys or mouse clicks (no `SendKeys`, no `SetCursorPos`).

## Commands

```bash
cargo run --release -- "<folder or file.md5>"   # argument optional; a .md5 then applies exactly as given
scripts/quality.sh all                          # like CI: guard check, fmt, clippy, tests with coverage, osv-scanner
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo test history                              # single tests by name
cargo deny check                                # vulnerabilities, licenses, sources (deny.toml)
cargo audit                                     # also lists what deny.toml skips for egui
pwsh tools/screenshot.ps1                       # README image: screenshots/veritas-main.png (+ -dark), from docs/examples, English; -Lang de for another language
```

On Windows, `cargo` is in `%USERPROFILE%\.cargo\bin`. `rust-toolchain.toml` pins 1.99.0. `build.rs` embeds `assets/icon.ico` and the version info on Windows (`winresource`, needs `rc.exe` from the Windows SDK). The release exe is a windowed program (`windows_subsystem`), so stderr is visible only when redirected; CI waits for the line `start-up: window ready`.

Packages (what the CI jobs `package-windows` / `package-linux` run after `cargo build --release`):

```bash
pwsh packaging/windows/build.ps1   # dist\windows: Veritas\, veritas_<v>_x64-portable.zip, veritas_<v>_x64-setup.exe
packaging/linux/build.sh           # dist/linux: veritas_<v>_amd64.deb, veritas_<v>_x86_64.AppImage (Ubuntu 24.04 only)
```

`build.ps1` needs only `cargo-packager` (for the installer), no Visual Studio tools: the C runtime is linked statically (`.cargo/config.toml`, `+crt-static`), so no DLLs are shipped. The script aborts if the exe imports the dynamic runtime (for example because an environment variable `RUSTFLAGS` overrides the setting). `packaging/windows/test-installer.ps1` installs and uninstalls in `%LOCALAPPDATA%\Veritas` – in CI only, never on a developer's machine.

## Product decisions (settled – build on them, don't re-propose alternatives)

| Decision | Why |
|---|---|
| Pure Rust + egui/eframe with `glow`, without `accesskit` | No WebView. `accesskit` is off because on Linux it pulls in quick-xml 0.30 with open advisories (RUSTSEC-2026-0194/0195). |
| The window **writes only MD5**, **reads and verifies SHA-1/256/512 too** | Product choice: writing stays MD5, SHA files are read for checking. `HashMode` has `Md5`, `Sha1`, `Sha256`, `Sha512` and `Both` (MD5+SHA-256, library only); `Digests` has one field per algorithm (`sha1`/`sha512` optional, old histories stay readable). `checksum::algorithm_of_name` recognizes SHA files by name only (case-insensitive): `*.sha1`, `*.sha256`, `*.sha512`, also `*.sha256sum` etc., `SHA1SUMS`/`SHA256SUMS`/`SHA512SUMS`, also with `.txt`. The name determines the algorithm; a line with a different hex length is discarded with a notice (a file without an algorithm in its name never counts). Formats GNU and BSD (`SHA256 (file) = hash`, `MD5 (…)` too), the same reader (`parse_line`/`parse_tagged`) with the same path rules, limits and encodings. Verify computes only the file's algorithm; the history names it in `hash_mode` (`"sha256"`), a field of its own is not needed. Column, status bar, context menu and source tag name the algorithm. **Create MD5** while a SHA file applies writes `{folder name}.md5` beside it (`checksum::names_for`; history `{folder name}.json`, the same one as when verifying the SHA file), reads every file (`Known` matches only for MD5), asks only if the `.md5` already exists (`Preview::md5_recorded` returns its entries), afterwards the `.md5` applies. Foreign SHA files in the folder are not hashed and do not count as *new* (`scanning::drop_foreign_checksums`, the preview likewise) – unless the applying checksum file names them; `list::protected` blocks deleting any checksum file in the folder. |
| The file is called **`{folder name}.md5`**, never `checksums.md5` | If it is not there, the only other `*.md5` applies, with several the newest (`checksum::choose_md5_file`); if there is no `.md5`, a SHA file (the newest, with equal time SHA-256 before SHA-512 before SHA-1). An explicitly opened checksum file (argument, drop; `.md5` or SHA) applies instead of this rule as long as the folder stays selected (`VeritasApp::pinned_md5`). |
| Format like md5sum: **uppercase hex, two spaces, `/`, `\n`** | Reading accepts lowercase, ` *` (binary) and **one** space (many Windows tools) too. Encoding: UTF-8 (with BOM too), UTF-16 with BOM, otherwise Windows-1252 (with a notice). `checksum::normalize_relative` normalizes paths: on Windows `\` is a separator; `./` and empty segments drop out; `..`, absolute paths, UNC, `\\?\` and (on Windows) any colon are rejected. Before opening and deleting, `scanning::contained_file` checks: regular file, no link, canonically below the folder. Limits: `.md5` 256 MiB, history 1 GiB. |
| **History instead of a backup copy**: `{folder name}.json` = `{"format": "veritas-verlauf-1", "runs": [...]}` | No `.md5.bak`. Every create and verify appends a run (`report::History`), without trimming. A replace run (`action: "created"`, `baseline: false`) records `modified` (old/new), `added`, `removed` and errors with `old_hash` – together with the new `.md5` that yields the old one. A report in the single-run format up to 0.5.0 becomes the first run; a foreign file is replaced with a warning. **Values in English**: `action` `created`/`verified` (`report::Action`), `integrity_status` `intact`/`possibly damaged`/`not checked` (`IntegrityStatus`), reasons, messages and warnings from the English templates of `i18n::Msg` – independent of the interface language. serde reads the German values of older histories as aliases, `i18n::shown` recognizes their texts by the German template; the display is always in the chosen language. Field names and the format identifier stay. Old runs are written back with English fixed values too; versions before the language choice no longer read that and replace the history with a warning. |
| **Opening does not hash** | `preview::preview_files` reads the folder and the `.md5`: if the file exists (in subfolders too, via `plain_file_meta`, which follows no link), it is *pending*, otherwise *missing*. Only *Verify* (F5) reads every file. |
| **Subfolders off** = entries in subfolders stay out | Verify does not report them as missing, create takes them over unchanged (`scanning::split_nested`). |
| Structure check **only on a hash mismatch** | `integrity::check_path` reads only head and tail (JPEG EOI after SOS in the last 64 KiB, data after it is intact – DJI drones append padding; PDF `%%EOF` in 2048, PNG chunk by chunk up to IEND, TIFF/BigTIFF, MP4 atoms by seeking to the end, ZIP via the central directory up to 16 MiB/100,000 entries; QuickTime without `ftyp` intact, OLE Office not checked). A hint, not proof. |
| **Create after verify reads only new/changed files** | After a verify with few mismatches, *Create MD5* used to read every file again. A finished run returns `ScanOutcome::known` (`scanning::Known`: per file checksum, size, modification time, structure finding); `VeritasApp::known` keeps it, `load_preview` discards it (folder change, subfolders, another `.md5`, failed run). Only create uses it (`Known::usable_for`: same folder, subfolders, algorithms, `.md5` unchanged by size/time), verify always reads everything. A file is taken over if its `fs::symlink_metadata` (size, time) is the same now as before and after it was read back then; if the modification time back then was less than 2 s (`MTIME_SLACK`, FAT/exFAT) before the read started, or in the future, it is not taken over. The walk stays fresh; the replace run in the history is the same in substance, a warning says “N checksums reused from the last verification …, M read”. No switch. Limit: content changed with the same size and a restored time is only seen by verify. |
| **Interim state in the list every 2 s** | During a long run, the state of the files already read should be visible. The run thread classifies every file it has read at once – verify by `report::verdict` (the same rule as `classify`, against the run's `.md5`, `path_key`), create as *pending* as at the end, read errors with a reason, reused checksums right after `split_known` – and puts them into `Progress::push_live`. `poll_job` collects them at most every `LIVE_SECS` (2 s, `input.time`) with `take_live`; `list::Live` applies them to the existing rows through a `path_key` index (one new version per collection, path index and search keys stay). Rows are neither added nor removed (nothing moves under the pointer): new files in subfolders (the preview does not know them) and *missing* are shown only by the result, *mismatch* is provisional – *damaged* comes with the structure check at the end. At the start, `Live::reset` sets results of an earlier run (ok, mismatch, damaged, error) back to *pending* – or to *new* if the `.md5` does not name the file – so that what is done can be told from the rest; *missing* stays as the last known state, as the preview shows it without reading. `Live` remembers the overwritten state per row; a cancelled or failed run restores the list from it, a finished one replaces it as before. |
| A cancel writes **nothing** | Neither `.md5` nor history. Writing is atomic: remove an existing `.partial`, create it with `create_new` (follows no link), the history first, the `.md5` renamed last. If the history cannot be written while verifying, the result still appears with a notice; an unreadable history is never replaced by an empty one. |
| Symlinks are not followed | Special files are skipped; the chosen folder itself may be a link. |
| On Windows compare file names **case-insensitively** | `report::path_key` with `FOLD_CASE = cfg!(windows)`, in `classify` and in the preview. |
| Colors: grey *pending*, **violet *new***, green *ok*, yellow *mismatch*/*missing*, red *damaged*/*error* | *Pending* is neutral, blue means only “selected”. Violet for *new* because grey *new* could not be told apart from *pending*. Violet is an app content color, not a design-system token: `Palette::new`/`new_bg`, `Tag::New`; also *new* in the history card, *added* (when creating) stays neutral. Status always as a tag with text. |
| File list **light on `surface` (white)**, dark on `bg` | On `bg` #F2F4F7, selection, hover and tag surfaces were barely visible. `Palette::list` carries the choice; contrasts are checked by `theme::tests::text_meets_aa_where_it_is_painted` and `selection_is_visible_where_it_is_painted`. |
| Table and tree rows **28 px** instead of 32 | Deliberate exception from the design system's 32 px row height, to keep the file list dense. |
| Disabled **primary and danger buttons** keep their fill, text white semi-transparent (`on_fill_disabled`, ~2:1) | A deliberate deviation from the design system's disabled-text token (`text-disabled`): on `accent-fill`, the dark `text-disabled` would have only 1.5:1. |
| Confirmation before replacing as a **dialog card** | As the design system prescribes for confirmations; Enter replaces, Esc or a click outside keeps. |
| **Five languages**, switchable through the icon beside About | German, English, French, Spanish, Italian. The language button (Lucide `languages`) left of About opens a list (each language in itself, the chosen one checked; as wide as its content, `theme::choice_width`, deliberately narrower than the design system's 240 px menu width), **Ctrl+L** switches to the next. The choice is stored in the settings (`Settings::language`); at the first start the system language (`sys-locale`), otherwise English. German is the original, the other four are fully translated. Where something is counted, the status word takes the language's plural (`Texts::counted`: “2 mismatches”, “2 modifiés”, “faltan 2”; German predicative “2 abweichend”); the filter chips show the base form like the list – they are the filter's name, and their width must not change when the count jumps from 1 to 2 during a run (nothing moves under the pointer). The README image is English. Files never depend on the language: `.md5` without text, history and logs in English. Tests run in German. |
| **Deleting** only into the trash and **always with a confirmation** | Deliberately against the design system's rule “undoable instead of asking”. Del or context menu → dialog card → `trash::delete`. The *Move to Recycle Bin* button is a **primary button** (blue), not a danger button – the trash is undoable; red stays for replacing the `.md5`. On Windows not on network and removable drives (`no_trash`, `GetDriveTypeW`) – there would be no Recycle Bin. Veritas never deletes the `.md5` or the history. The `.md5` stays unchanged; the file is *missing* afterwards. Tests set `VeritasApp::trasher` to a stub. |
| History **at the file**, no button in the toolbar | A small clock icon at the right of the *File name* column, only if the history names the file. Plus Ctrl+H and the *History* row. |
| **No mmap**, buffered reads | Measured on 2026-10-18: on Windows mapped pages stayed in the process; verifying 57 GB of photos and videos took 2–4 GB of memory and triggered a Windows low-memory warning. Buffered is as fast or faster on NVMe. |
| On a **spinning hard disk (HDD) one file at a time** | Measured on 2026-10-18 (8 TB HDD, buffered): 1 thread 222–234 MB/s, 16 threads 164–178 MB/s. The *Threads* setting stays the upper limit; if the chosen folder is on an HDD, the toolbar shows a hard-disk icon beside *Threads* instead of the processor, and the tooltip names the exception. |
| **Settings in the toolbar, no popup** | The toolbar has few buttons, a cog with a popup is not needed. Right side of the toolbar: theme (`segments` with sun/moon/screen; parts 32 × 26 so that the group is 32 high like buttons and fields – instead of the design system's compact 24 or 32 × 30), │ subfolders (`toggle_icon_button`, folder tree) and threads (processor icon + `number_field`), │ search (140), language and About. Everything on the right has a fixed width, only the name of the `.md5` truncates (nothing moves under the pointer); at the smallest window size (`ui::MIN_SIZE`, 880 × 620) a test checks that nothing overlaps. **Ctrl+,** moves the focus into the *Threads* field (during a run a notice with the reason), **Ctrl+L** switches the language. There is no “without subfolders” note: the switch shows the state. |
| F1 shows only *About Veritas* | No tabs for keys and tips. The keys are in the tooltips, in the empty state and in `docs/manual.md` (the most important ones in the README too). |
| egui stays (Tauri checked on 2026-11-19: AppImage 70–100 MB, more memory, porting would take weeks) | The build gets smaller through the release profile in `Cargo.toml`: `opt-level = "s"` (`"z"` got bigger), fat LTO, `strip = true`; `md-5`, `sha1` and `sha2` stay at `opt-level = 3` (without it SHA-256 drops by about 14 %). **No `panic = "abort"`**: `poll_job` catches a crashed run thread. `strip` removes the function names from `crash.log` on Linux; message and code location stay. Windows: static C runtime (`.cargo/config.toml`), no embedded fonts; `default_fonts` only on Windows as the last fallback, the feature `links` is off (`open` opens the links). After changes to the profile, measure hash throughput again (`hashing::hash_slice` on 1 GiB, release; reference MD5 ≈ 735 MiB/s, SHA-256 ≈ 2250 MiB/s on the reference machine). |

## Architecture

| `src/integrity.rs` | Structure check per format |
| `src/progress.rs` | Progress between the run thread and the interface, with the file being hashed and the result per file read (`LiveRow`, `push_live`/`take_live`) |
| `src/crash.rs` | Panic hook: appends message, code location, version and call chain to `crash.log` in eframe's data folder (`adopt_old_log` renames an `absturz.log` of older versions at start-up as long as there is no `crash.log`); both logs always in English; `VeritasApp::note_crash` points to it once at the next start (`Settings::crash_seen`). | `deny.toml`, `.github/dependabot.yml` | Rules for `cargo deny`; monthly updates of the pinned actions and the dependencies |
| `tools/make_lucide_subset.py` | Cuts the Lucide subset from `lucide-static` 0.460.0 |

A run happens in a thread of its own (`veritas-scan`), the result comes through a channel; `poll_job` picks it up. During a run, changing the folder, dropping, and subfolders and threads in the toolbar are locked – with the reason in the tooltip; `run` takes the focus away from the *Threads* field, otherwise Esc would go to the locked field. Canceling works until shortly before writing (`Progress::begin_writing` / `request_cancel`); if the run is already writing, it finishes, and `on_exit` waits up to 10 s for it. Opening a folder also reads in the background (`veritas-vorschau`): the folder is selected at once, the list says *Reading…*, runs wait with a reason; every request has a channel of its own (a stale result never arrives) and a stop signal that makes a replaced one stop early; arrow keys in the tree read only after 150 ms of rest.

## Tests

Tests live in the module (`#[cfg(test)]`). `ui::tests` drives the whole window without a display: both themes, the toolbar at the smallest window size in every language (`the_bar_fits_the_smallest_window`: nothing overlaps, the name of the `.md5` keeps 80 px + 5 %), the language menu and Ctrl+L (`the_language_menu_and_ctrl_l_switch_the_language`) and its settings (`the_bar_holds_the_settings`, clicks as `PointerButton`), notice, dialog cards, *About Veritas*, history card; key flows through `egui::Event::Key`; real runs in temp folders. After `select_folder`/`open_path`, `settle(&ctx)` waits for the preview (blocking on the channel, without sleeping). Tests run in German; `i18n::set` acts only on its own thread in tests. `i18n::tests` check every language: every text with values renders them, labels with a fixed space fit (`fixed_labels_fit_in_every_language`), counted statuses take singular and plural (`counted_statuses_take_the_plural`), French keeps punctuation with a non-breaking space; `history::tests` read a German history and a mixed file.

## Release

1. Raise the version in `Cargo.toml` (the one source; *About Veritas* shows it).
2. `CHANGELOG.md`: rename `[Unreleased]` to `## [X.Y.Z] – YYYY-MM-DD`, one sentence below it, a new empty `[Unreleased]` above.
3. Commit to `main`, push, wait for CI. Every push runs Linux and Windows (lint & test), the packages and the workflow check (`actionlint`, `zizmor`). (`ci.yml` runs a leaner set while the repository is private – condition `github.event.repository.private`.)
4. Only when the maintainer says so: `git tag -a vX.Y.Z -m "Veritas X.Y.Z"` and `git push origin vX.Y.Z`. CI builds all packages and creates a release draft (the `release` job checks that the tag and `Cargo.toml` agree; the notes are the version's CHANGELOG section, the job aborts if it is missing; a build provenance attestation is added).
5. Look at the draft (text, files, checksums), then `gh release edit vX.Y.Z --draft=false --latest`.

## Gotchas

- The measure is the UI design system (see Standards). Only tokens from `theme.rs`, no hex values outside it. Contrasts are checked by `theme::tests::text_meets_aa_where_it_is_painted` – enter new color pairs there.
- Do **not** set `spacing.interact_size.y` to 32 (`ui.horizontal` takes its starting height from it); heights come per building block.
- A disabled `Ui` greys everything towards `surface`. The building blocks therefore paint with `token_painter` and set `disabled` themselves.
- Click areas with `Sense::CLICK`, not `Sense::click()` – otherwise they take keyboard focus.
- An `Area` is invisible in the first frame; tests run two frames.
- `TextEdit::min_size` is the outer size; since egui 0.37 the response `rect` is the outer one too (border included) – `theme::tests::text_field_reports_its_outer_frame`.
- egui 0.37: `App::ui` gets a `Ui`, panels are called `egui::Panel::top/bottom/left` and show in that `Ui`; measuring text needs `ctx.fonts_mut`. Tests without a display call `Context::run_ui` and must call `textures_delta.clear()`, otherwise a debug check in epaint trips.
- Without the feature `monochrome_emoji_fonts`, epaint 0.37 has no emoji fonts; font families therefore do not name built-in fonts (`fonts::build`); a name is in a family only if its data is there. A family without a font draws nothing, and missing glyphs are painted only as boxes (no error): new characters in interface texts are checked by `fonts::tests::every_ui_character_has_a_glyph_without_system_fonts`.
- Lucide is second in every font family; the egui fonts behind it occupy some code points in the private use area.
- **Texts only via `i18n`**: a new interface text is a field in `Texts` with a doc comment and appears in all five files (otherwise a compile error), translated with the core terms from the language's module comment; the space tests (`cargo test i18n`) must stay green. A text that goes into the history is a `Msg` with a German and an English template plus a line in the `msg` of `fr`/`es`/`it`; changing a template changes the file format (old texts are then no longer recognized). Never build what is stored with `i18n::t()`. Whoever keeps a text in the UI that outlives a language uses `Say`, not a `String`.
